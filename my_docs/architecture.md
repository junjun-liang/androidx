# AndroidX 项目软件架构设计文档

## 1. 项目概述

AndroidX 是 Google 官方的 Android Jetpack 库集合，采用单一大型 Monorepo 结构管理。项目包含超过 450 个子模块，涵盖 UI 框架、架构组件、数据存储、平台集成、性能优化等 Android 开发的各个领域。所有库独立于 Android OS 发布，专注于提升应用开发体验，提供跨 OS/设备的兼容性、高层抽象简化平台特性、以及针对开发者痛点的新功能。

### 1.1 项目基本信息

| 属性 | 值 |
|------|---|
| 项目类型 | Android Jetpack 官方库集合 |
| 代码管理 | Monorepo（单仓库） |
| 子模块数量 | 450+ |
| 构建系统 | Gradle + 高度定制 buildSrc |
| 编译 SDK | 34 |
| 目标 SDK | 36 |
| JVM 内存 | 12GB |
| Kotlin 版本 | 2.1 |
| Java 兼容性 | Java 17 |
| 多平台支持 | Kotlin Multiplatform (KMP) |
| 构建输出目录 | `../../out` |

### 2.2 架构分层说明

| 层级 | 名称 | 职责 | 代表模块 |
|------|------|------|---------|
| L5 | 应用集成层 | 特定应用场景的完整解决方案 | Car App, Wear, XR, TV, Health |
| L4 | UI 框架层 | 用户界面渲染与交互 | Compose, AppCompat, Graphics, Ink, PDF |
| L3 | 架构组件层 | 应用架构模式与状态管理 | FLAN, Work, Paging, Hilt, DataStore |
| L2 | 数据存储层 | 数据持久化与访问 | Room3, SQLite, DataStore, Collection |
| L1 | 平台集成层 | Android 平台能力封装 | Core, Window, Camera, Browser, WebKit |
| L0 | 基础设施层 | 最底层基础工具与注解 | Annotation, Concurrent, Tracing, Kruth |

**设计原则：**
- 多平台优先：逻辑优先在 `commonMain` 实现，平台特定代码放 `androidMain`
- Modifier.Node：高性能 Modifier 实现，避免 `composed {}`
- API 可见性：优先公共 API，`@RestrictTo` 仅在必要时使用

## 6. 版本管理策略

### 6.1 语义化版本控制

| 版本段 | 格式 | 含义 | 兼容性 |
|--------|------|------|--------|
| Major | x.0.0 | 破坏性 API 变更 | 不兼容 |
| Minor | 1.x.0 | 兼容的公共 API 新增 | 二进制兼容 |
| Bugfix | 1.0.x | 内部行为修复 | API 不变 |

### 6.2 预发布周期

```
alpha → beta → rc → stable
  │       │      │      │
  │       │      │      └── 正式发布
  │       │      └── 发布候选（仅修 bug）
  │       └── 功能冻结（仅修 bug）
  └── 功能开发中
```

每个阶段至少持续 2 周。

### 6.3 分支策略

```
┌───────────────────────────────────────────────────────┐
│  androidx-main (单一开发分支)                          │
│  ├── alpha/beta 开发                                  │
│  ├── 所有新功能在此提交                                │
│  └── cherry-pick → androidx-<feature>-release         │
│       ├── 仅包含 rc/stable 版本                        │
│       ├── 仅通过 cherry-pick 修改                      │
│       └── 新 minor 版本时从 main 重新 snap            │
└───────────────────────────────────────────────────────┘
```

### 6.4 API 跟踪工具

| 工具 | 用途 |
|------|------|
| `checkApi` | 确保公共 API 变更是有意的 |
| `checkApiRelease` | 验证 API 变更符合语义化版本保证 |
| `updateApi` | 将 API 变更提交到源码控制 |
| `api/current.txt` | 追踪公共 API 变更 |
| BCV (Binary Compatibility Validator) | KMP 二进制兼容性验证 |

## 9. 设计原则

AndroidX 遵循 14 条核心设计原则：

1. **优化外部客户端采用** - 主要面向第三方开发者
2. **满足真实用例** - 解决开发者实际痛点
3. **感知现有生态** - 不重复造轮子
4. **与 Jetpack 一致** - 概念跨组件一致
5. **开源且兼容 AOSP** - 在 AOSP 中开发
6. **语言惯用 API** - Kotlin 和 Java 都自然
7. **广泛 API 级别兼容** - write-once, run-everywhere
8. **集成最佳实践** - 引导使用架构组件
9. **为工具和可测试性设计** - 提供 `-testing` artifact
10. **明确发布流程** - 语义化版本控制
11. **良好文档** - 入门文档 + API 参考
12. **长期支持** - 规划长期维护
13. **现代开发范例** - Kotlin 优先，最新 SDK
14. **高质量 API 和所有权** - 遵循 API 指南
